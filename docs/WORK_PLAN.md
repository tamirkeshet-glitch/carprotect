# תוכנית עבודה — CarProtect

## 1. חזון ומטרות
אפליקציה פשוטה לבדיקת רכב לפני קנייה:
- צילום לוחית (או הקלדה ידנית).
- דו"ח מלא: מספר בעלויות, האם היה בעלות חברה/ליסינג/השכרה, ק"מ אחרון, תוקף טסט, ריקולים, סטטוס פעיל/ביטול סופי.

עדיפות: שאיבה ישירה ממקורות פתוחים (data.gov.il) ולא דרך ספקי צד ג'.

### מגבלות
- אין היסטוריית תאונות/תביעות ביטוח מלאה.
- אובדן להלכה — אין שדה ציבורי ברור (רכבים באובדן גמור לוחים במאגרי ביטול).
- היסטוריית בעלות עיקרית מ-2017.
- שעבודים — רשם המשכונות (לא פתוח ב-data.gov.il).
- עדכון יומי/תקופתי (לא זמן אמת מלא).

## 3. זרימת משתמש (User Flow)
1. צילום לוחית → OCR (מקומי או שרת).
2. שליחת מספר רכב ל-backend.
3. שאילה מקבילית למאגרים.
4. נירמול והצגת דו"ח צבעוני (ירוק/צהוב/אדום).
5. שיתוף PDF / וואטסאפ.

## 4. ארכיטקטורה
### שכבת לקוח
- Flutter או React Native.
- OCR: Google ML Kit / Apple Vision.
- UI מותאם לסוחרים (סריקה מהירה + היסטוריית חיפושים).

### שכבת שרת
- Python FastAPI או Node.js.
- שאילות מקבילות + Cache (Redis, 12–24 שעות).
- נירמול נתונים: ספירת ידיים, דגל בעלות חברה/ליסינג.

### מסכים עיקריים
1. מסך בית — צילום / הקלדה.
2. מסך דו"ח — כרטיסים צבעוניים.
3. שיתוף / ייצוא PDF.

## 5. שלבי MVP
1. Backend פשוט שמושך לפי מספר רכב ומחזיר JSON מסודר.
2. אב-טיפוס או אפליקציה עם OCR.
3. תצוגת דו"ח ידידותית לסוחר.
4. Cache + היסטוריית חיפושים.
